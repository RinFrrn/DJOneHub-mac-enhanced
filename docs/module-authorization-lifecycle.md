# 模块授权生命周期：一次 Mac 初始化，之后仅用 iPhone

更新：2026-09-12。

目标是首次通过受信任的 Mac 安装模块程序，此后绑定恢复、换手机、撤销授权和提醒配置都由 iPhone 与模块完成，不依赖项目服务器。

## 当前实现状态

本次完成的是**独立授权管理闭环的第一阶段**，不是现有通话配对的全面替换。新服务默认关闭，iOS 已编入客户端和凭据管理代码，尚未提供用户操作界面。

## 凭据与信任

- 模块 ID 使用独立的 128 位随机值，证书使用独立 P-256 密钥；手机换机或撤销不会改变模块身份。
- 手机使用本机生成的 256 位随机凭据，通过 TLS 提交。模块保存 SHA-256 哈希，iPhone 保存在独立的 `module-authorization.v1` Keychain service 中。
- 首次绑定码和恢复码各自独立生成。首次码 15 分钟有效，完成绑定后删除其哈希；恢复码没有定期失效要求。
- TLS 固定为 1.3，验证首次可信资料中的完整证书 SHA-256 指纹。模块持有对应私钥，TLS 握手产生新会话密钥；不从网络自动更新指纹，不依赖公共 CA 或在线验证服务。证书为固定设备身份，日期覆盖 1970 至 9999 年，避免定期证书续期把用户带回 Mac。
- 本地管理端点固定为 USB ECM `192.168.225.1:45754`，不接受自定义远程管理地址。用户可配置的 Bark/推送 URL 属于另一层设置，不能改变模块身份验证地址。
- 每个模块最多授权 4 台手机，当前每台已授权手机均可管理设备授权。并非访客/只读授权模型。
- 恢复码是控制权凭据，应保存在用户离线备份或密码管理器中。手机凭据与恢复码同时丢失时，需要受控的模块物理恢复操作；现阶段没有无凭据远程重置接口。

## 绑定与恢复事务

1. iPhone 校验初始化/恢复资料，生成手机凭据，将待完成记录保存到 Keychain。恢复场景同时生成下一份恢复码。
2. `prepare` 校验首次码、恢复码或已授权手机，保存一个有效期 10 分钟的待确认记录。已有手机继续有效，新手机还没有一般访问权限。
3. iPhone 保存模块返回的设备 ID，引导用户备份恢复资料，确认备份后调用 `commit`。
4. 模块以一个原子文件更新确认授权。恢复操作同时清空旧手机列表、替换恢复码；首次绑定码失效。请求不修改 Bark、VAPID、证书配置或旧通话密钥。
5. iPhone 将待完成记录转为长期授权。如果响应丢失或本地最终保存失败，原先保存的待完成凭据可再次 `commit`，不会重复授权或改变模块身份。

`cancel` 可以取消尚未确认的记录，支持响应丢失后的重试。已经确认的凭据不能通过取消操作丢弃，必须继续完成本地保存或显式撤销。过期的待确认记录不会撤销当前手机。

恢复操作可覆盖普通手机发起的待绑定，避免丢失的旧手机不断发起绑定阻碍找回。已撤销手机发起的未完成授权同时取消。管理请求每次读取当前注册表，不以存活的 TLS 会话缓存手机权限。

状态文件使用进程排他锁、0600 临时文件、文件同步、原子重命名和目录同步。拒绝不安全权限、符号链接文件及损坏状态，初始化不会覆盖已有状态。各请求重新读取磁盘，避免重命名成功但同步返回错误后继续使用旧内存授权。

时间仅用于短期绑定码和待确认事务；已确认的手机授权没有时间到期条件。首次安装应同步模块时钟，短期事务拒绝明显的时钟回拨。实际断电行为仍需在模块文件系统上验证。

## 开发验证入口

在 Mac 上生成一套**新的**资料，输出目录必须不存在，且不要放在仓库内：

```sh
go run ./cmd/djonehub-pairing-prepare -out /tmp/djonehub-new-module-private
```

工具不会连接或改写模块，不会输出任何密钥。输出目录和文件均为私有权限：

- `registry.json`：仅此文件用于安装到该模块，包括模块私钥及授权注册表；不能克隆给其他模块。
- `bootstrap.json`：iPhone 首次绑定资料。
- `recovery.json`：该模块的离线恢复资料，**不要安装到模块**。
- `registry.json.lock`：本地进程锁文件，无需安装。

实验固件可向现有 `djonehub-notify` 追加以下参数启用管理服务，使用同一 Go 进程，避免增加常驻运行时：

```text
-experimental-pairing-registry /usrdata/djonehub/pairing/registry.json
```

父目录须为 0700，注册表须为 0600。这个参数不执行初始化，不触碰现有 `pairing.key`，不改变旧服务授权。正式安装器目前不会自动添加它。向导交付前还应加入一次安装资料销毁/保留提示和恢复资料备份确认。

iOS 接口位于 `ModuleAuthorization.swift` 和 `ModuleAuthorizationClient.swift`。`begin → prepare → confirmRecoveryBackup → commit` 为绑定流程；恢复时使用 `module-recovery` 资料，并通过 `replacementRecoveryInvitation` 取得需要离线保存的新恢复资料。`status` / `revoke` 处理已授权手机；`cancelPending` 只清除模块确认未生效的事务。

## 正式迁移之前必须完成

1. 让通话、短信、PCM 和提醒使用同一份授权决策，不能把新长期手机凭据转换为可绕开注册表撤销的旧共享密钥。音频中的活动会话也要结束或重新认证。
2. 定义版本协商和受控迁移。有效控制配对可证明旧设备持有权；只读、过期或损坏开发凭据不能因 App 升级自动变为长期管理员。现有全局 Mac 密钥缓存不能成为新模块的身份来源。
3. 确认迁移成功后才禁用旧授权入口；失败要保留已验证的恢复途径。禁止在旧服务仍接受开发密钥时宣布撤销完成。
4. 将提醒设置、服务证书导入切到加密管理通道。Bark 地址、隐私开关、VAPID 等继续独立保存，授权更换不重置这些配置。
5. 接入 iPhone 设置页面和旧手机授权新手机的交接流程，再制作 Mac 首次安装向导。
6. 实机验证长时间断开 Mac、模块重启、跨月使用、换机、恢复、撤销后的通话/短信/音频拒绝、事务中断电、时钟异常及丢失全部凭据时的物理恢复。

## 验证

```sh
go test -race ./internal/modulepairing ./internal/modulepush ./cmd/djonehub-pairing-prepare ./cmd/djonehub-notify
swift test --package-path ios/DJOneHubUACProbe
```

已验证：Go 授权状态机、存储权限、并发绑定、恢复、撤销、取消、超时、时钟回拨、TLS 实际握手与错误指纹拒绝；Swift 资料解析、长期记录、指纹和 HTTP 边界；DJOneHub iOS Simulator 构建；包含实验服务的静态 ARMv7 soft-float 编译及 ELF 审计。

尚未验证：iPhone 与真实模块间的 Network.framework TLS 联调、模块上新增服务的运行内存峰值，以及真实断电恢复。ELF 审计仅检查目标 ABI/BSS，不代表 TLS 实机内存已经通过。
